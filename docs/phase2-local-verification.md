# Phase 2 — local verification, not a production rollout

`gateway.make_app` uses a worker-local `SessionManager` with the real ACP backend. A tool response ends an HTTP request, not the producer's `session/prompt`. The IPC handler accepts registered client tools only, validates their arguments, and waits for a result. The HTTP client executes the tool. The final producer result, not the continuation request's input length, provides billing usage.

- The bridge token is stored in a `0600` file inside a separate `0700` directory under `/tmp`; only the file name is passed on the bridge command line. The socket is in this short, private directory, outside the agent workspace.
- Distinct credentials in `GATEWAY_API_KEYS_JSON` (`principal: key`) have distinct session namespaces. A dedicated `X-ACP-Session-Key` can further separate sessions. Implicit transcript-prefix reuse is deliberately disabled for the undivided shared gateway key; users of this key can still continue by unguessable call/response ID. Never share a credential between mutually untrusted tenants.
- Known duplicate, expired or incompatible tool results fail closed. Unknown tool IDs return 409 by default. `ACP_ALLOW_COLD_TOOL_REPLAY=1` opts into cold replay only for stateless requests with the local worker's ID format and matching invocation and task history. Not appropriate for workflows where a repeated side effect would be unsafe.
- Worker limits: `MAX_WARM_SESSIONS=32`, `MAX_TOTAL_SESSIONS=128`, `SESSION_WARM_TTL=300`, `SESSION_IDLE_TTL=1800`, `TOOL_WAIT_TIMEOUT=300`. The sweep interval is 30 seconds; incoming tool results check their deadline directly. No cross-worker session migration. Do not enable this path in a multi-worker pool without routing continuations to their original worker.

## Evidence

- `test_session_bridge.py` drives real HTTP, a local fake ACP child, and real MCP stdio/Unix IPC. It checks single and parallel calls, process/PID and prompt counts, 64 KiB tool history, tenant isolation, branch detection, resume and fallback, explicit headers and previous response IDs, timeouts, duplicate submission, output budgets, and disconnect/crash cleanup.
- `session_smoke.mjs` exercises the installed official OpenAI Node SDK using random client-only tool results. Set `OPENAI_SDK_PATH`, `PORT` and `GATEWAY_API_KEY` to point to the SDK and a disposable loopback gateway. The single- and two-call probes both returned their random values. Intermediate HTTP responses had no billing usage, all follow-ups were `X-ACP-Session-State: tool`, and both final responses contained settled usage.
- Original Pi CLI, Anthropic protocol, two random files accessible through its local `read` tool: both contents matched. Three HTTP responses: `tool_call` (cold), `tool_call` (hit), `stop` (hit), all 200.
- HIGH `gemini-4-neon` with a multistep deduction problem: real Chat SSE returned one native reasoning summary frame and thirteen text frames. An earlier counting problem emitted a summary but ended without visible text (reported as an upstream error, not a successful empty answer).
- Initial Claude Code and Codex probes exceeded the 90-second probe deadline. Not claimed as Phase 2 passes. Production routing, failure injection under load and the full four-CLI acceptance matrix are separate from these local checks.
